# Story 1.1: Empty Profile State & Error Handling

## Status
Draft

## Story
**As a** new user who has just signed up,
**I want** to see a welcoming empty state when I have no profile,
**so that** I understand I need to create a profile and feel guided to do so.

## Acceptance Criteria
1. When a user navigates to `/profile` and the API returns 404 (no profile exists), the page displays an `EmptyProfileState` component with:
   - Welcome heading: "Welcome to Your Profile"
   - Descriptive text explaining benefits of completing a profile
   - Clear call-to-action button: "Create Your Profile"
   - Optional illustration or empty state graphic
2. When the "Create Your Profile" button is clicked, the page transitions to show the onboarding wizard (Step 1 visible).
3. When API returns authentication error (401), the user is redirected to `/login` with a message: "Your session has expired. Please log in again."
4. When API returns network error or 500 server error, a toast notification displays: "Unable to load profile. Please try again." with a "Retry" button that refetches profile data.
5. All error states maintain the existing dashboard layout (header/navigation visible).

### 2. Implement `EmptyProfileState` Component (AC1, AC2)
- [ ] **LEARN: Creating Components and Passing Props.**
  - **Suggested Focus Time:** 30-60 minutes.
  - **Details:** A component is a reusable piece of UI. Props are how you pass data to it. This is a core concept.
  - **Resource:** Review [Your First Component](https://react.dev/learn/your-first-component) and [Passing Props to a Component](https://react.dev/learn/passing-props-to-a-component).
  - **Resource:** See how to type props in TypeScript with [this guide](https://www.typescriptlang.org/docs/handbook/react.html#components).
- [ ] **DO: Create the `EmptyProfileState.tsx` file.**
  - **File Path:** `apps/web/components/profile/EmptyProfileState.tsx`
  - **Action:** Create the component with a heading, text, and a button as specified in AC1.
- [ ] **LEARN: Handling User Events and State.**
  - **Suggested Focus Time:** 1-2 hours.
  - **Details:** You need to make the button interactive. The key concept here is **Lifting State Up**.
  - **Focus:** The `EmptyProfileState` component itself will *not* have state. The *profile page* (the parent) will hold the state, and your component's button will simply call a function passed down from the parent.
  - **Resource:** Read about the `useState` hook: [useState Hook](https://react.dev/reference/react/useState).
  - **Resource:** Learn how to handle clicks: [Responding to Events](https://react.dev/learn/responding-to-events).
  - **Resource:** Understand how a child component can notify a parent: [Lifting State Up](https://react.dev/learn/sharing-state-between-components).
- [ ] **DO: Wire up the "Create Your Profile" button.**
  - **Action:** The component should accept a function via its props (e.g., `onCreateProfile`). The button's `onClick` event should call this function.

- [ ] **LEARN: Conditional Rendering.**
  - **Suggested Focus Time:** 15-30 minutes.
  - **Details:** You'll need to show the `EmptyProfileState` only when there's no profile. The `&&` operator is a common shortcut for this.
  - **Resource:** Read about [Conditional Rendering](https://react.dev/learn/conditional-rendering) in React.

  - **File Path:** `apps/web/app/(app)/profile/page.tsx`

    2. Based on the `profile` data it returns, render either the existing profile view or your new `EmptyProfileState` component.

### 4. Integrate Error Handling (AC3, AC4)
- [ ] **LEARN: Handling Errors from Hooks.**
  - **Suggested Focus Time:** 15-20 minutes.
  - **Details:** The `useProfile` hook provides an `error` object. You need to inspect it to handle different cases.
  - **Heads-Up:** As noted previously, the story requires checking for specific error codes (401, 500), but the hook in its current state may not provide this. This might require a code change to be fully implemented.
  - **Action:** Examine the `useProfile.ts` file to see what it returns.
- [ ] **LEARN: Redirects in Next.js.**
  - **Suggested Focus Time:** 10-20 minutes.
  - **Details:** For a 401 error, you need to send the user to the login page programmatically.
  - **Resource:** Learn about the `redirect` function: [Next.js `redirect` function](https://nextjs.org/docs/app/api-reference/functions/redirect).
- [ ] **LEARN: Using a Toast Library.**
  - **Suggested Focus Time:** 15-30 minutes.
  - **Details:** Toasts are small, non-blocking notifications. This project uses Sonner.
  - **Resource:** Look at the [Sonner Documentation](https://sonner.emilkowal.ski/) to see how to show different types of toasts (e.g., `toast.error`).
- [ ] **DO: Implement the error handling logic.**
  - **File Path:** `apps/web/app/(app)/profile/page.tsx`
  - **Action:**
    1. Check the `error` from `useProfile`.
    2. If it's a 401, call `redirect('/login?reason=expired')`.
    3. If it's a 500 or network error, use Sonner to show a toast with a "Retry" button that calls the `refetch` function from `useProfile`.
